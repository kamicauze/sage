# MCP Integration for Architect

**Target:** Enable Architect to work seamlessly with codebases that use various services (Supabase, Git, etc.)

**Philosophy:** Architect stays lightweight, but can interact with your project's infrastructure

---

## Priority 1: Git MCP (Must Have)

### Why This First
- You're working on projects that need version control
- Auto-commit generated code
- Create branches for features
- Essential for any serious development

### Implementation

```bash
# Install Git MCP Server
npm install -g @modelcontextprotocol/server-git
```

**Add to Architect API:**

```python
# architect/api/mcp/git_client.py
from mcp import Client

class GitMCPClient:
    def __init__(self, repo_path: str):
        self.client = Client("git")
        self.repo_path = repo_path

    async def create_branch(self, branch_name: str):
        """Create a new branch for a feature."""
        return await self.client.call_tool("git_create_branch", {
            "repo_path": self.repo_path,
            "branch_name": branch_name
        })

    async def commit(self, message: str, files: list[str]):
        """Commit generated files."""
        return await self.client.call_tool("git_commit", {
            "repo_path": self.repo_path,
            "message": message,
            "files": files
        })

    async def get_status(self):
        """Get current git status."""
        return await self.client.call_tool("git_status", {
            "repo_path": self.repo_path
        })
```

**Add Git Integration to Build Endpoint:**

```python
# architect/api/routes/builds.py
from mcp.git_client import GitMCPClient

@router.post("/build", response_model=BuildResponse)
async def execute_build(
    request: BuildRequest,
    auto_commit: bool = False,  # Optional flag
    branch_name: str | None = None
):
    # Load manifest
    manifest = load_manifest(request.manifest_path)
    repo_path = manifest['project']['paths']['repo_path']

    # Execute build
    result = builder.execute_plan(plan_path)

    # Optional: Auto-commit if requested
    if auto_commit and result['status'] == 'SUCCESS':
        git = GitMCPClient(repo_path)

        # Create branch if specified
        if branch_name:
            await git.create_branch(branch_name)

        # Commit changes
        await git.commit(
            message=f"feat: {request.query}\n\nGenerated by Architect",
            files=result['artifacts']
        )

    return result
```

## Priority 2: Filesystem MCP (Very Useful)

### Why This
- Better file operations than shell commands
- Watch for changes
- Handle large files efficiently

```python
# architect/api/mcp/filesystem_client.py
class FilesystemMCPClient:
    async def read_file(self, path: str):
        """Read file with proper encoding detection."""
        return await self.client.call_tool("read_file", {"path": path})

    async def watch_directory(self, path: str, callback):
        """Watch for file changes."""
        return await self.client.call_tool("watch_directory", {
            "path": path,
            "callback": callback
        })
```

**Use Case:**
```python
# Auto-detect when user manually edits generated code
fs = FilesystemMCPClient()

async def on_change(event):
    if event['path'] in generated_files:
        # User edited generated code - learn from it
        log_user_modification(event)

await fs.watch_directory(project_path, on_change)
```

## Priority 3: Supabase MCP (For Projects That Use It)

### Why This
- Many of your projects might use Supabase
- Architect can help you interact with Supabase in those projects
- Run migrations, query data, manage auth

**This is NOT for Architect's own data - it's for projects you're building!**

```python
# architect/api/mcp/supabase_client.py
class SupabaseMCPClient:
    """
    Use this when building projects that use Supabase.
    NOT for Architect's internal data.
    """

    async def run_migration(self, sql: str):
        """Run a Supabase migration."""
        return await self.client.call_tool("supabase_migrate", {
            "sql": sql
        })

    async def query(self, table: str, filters: dict):
        """Query Supabase table."""
        return await self.client.call_tool("supabase_query", {
            "table": table,
            "filters": filters
        })
```

**Example Use Case:**

```
User: "Add a posts table to my blog"

Architect:
1. Generates migration SQL
2. Uses Supabase MCP to run migration
3. Generates TypeScript types
4. Creates CRUD operations
5. Auto-commits everything via Git MCP
```

## Configuration

**Add to project manifest:**

```yaml
# architect/projects/sage.yaml
project:
  id: sage_brain
  # ... existing config

mcp:
  enabled: true
  servers:
    - name: git
      enabled: true
      auto_commit: false  # Default, can override per build

    - name: filesystem
      enabled: true

    - name: supabase  # Only if THIS project uses Supabase
      enabled: false
      config:
        project_url: ${SUPABASE_URL}
        anon_key: ${SUPABASE_ANON_KEY}
```

**Example for a Supabase project:**

```yaml
# architect/projects/my_web_app.yaml
project:
  id: my_web_app
  paths:
    repo_path: /home/user/projects/my-web-app

mcp:
  servers:
    - name: git
      enabled: true
      auto_commit: true  # Always commit

    - name: supabase
      enabled: true  # This project USES Supabase
      config:
        project_url: https://xxx.supabase.co
        anon_key: ${SUPABASE_ANON_KEY}
```

## Benefits of This Approach

### ✅ Keeps Architect Simple
- No cloud dependencies
- No authentication overhead
- Works offline
- Fast and lightweight

### ✅ Enables Powerful Workflows
```
# Example workflow
User: "Add user authentication with Supabase"

Architect:
1. Creates branch: feature/add-auth (Git MCP)
2. Generates Supabase schema (Supabase MCP)
3. Runs migration (Supabase MCP)
4. Generates auth components
5. Commits everything (Git MCP)
6. Returns: "Done! Branch: feature/add-auth"
```

### ✅ Project-Aware
- Each project can have different MCPs
- Sage might not use Supabase, but your web app does
- Architect adapts to each project's stack

### ✅ Optional & Incremental
- Start with just Git MCP
- Add others as needed
- No forced dependencies
